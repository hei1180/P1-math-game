# 裝備室 Shop UI/UX overhaul — Implementation Plan

> **For agentic workers:** use `superpowers:subagent-driven-development` / `superpowers:executing-plans`. Steps use checkbox (`- [ ]`) tracking. Read `docs/superpowers/specs/2026-10-10-treasure-dungeon-design.md` §4b (customization) first.

## 1. Why (what's wrong today)

Screenshot 1 — the 連身裙 / 盔甲 / 斧頭 / 鐵鎚 cards: a tiny mini-hero is jammed into the top third, the item itself is barely legible (the dress card reads as "a guy in a green tunic"), the weapon overlaps the hero and the name, and the art collides with the label.

Screenshot 2 — the 裝扮 tab: **flat colour circles** for 玫瑰膚 / 粉紅髮 / 薄荷衫 … They say nothing about what the hero will look like, and skin / hair / cloth colours are all mixed in one undifferentiated grid of 18 cards.

Root causes:
1. **One 裝扮 tab holds five different things** — skin colour, hair colour, cloth colour, outfit *shape*, and weapon — as `SHOP_LOOKS = [...COSMETICS, ...OUTFITS, ...WEAPONS]`.
2. **Colour cosmetics preview as a dot** (`card()` line ~163), not as the hero wearing them.
3. **Outfit/weapon cards reuse `makeHero` at a scale that fits a whole hero into ~40 px** — unreadable at P1 tablet size.
4. **The catalogue is thin**: 6 skins, 6 hair colours, 8 cloth colours, 5 hair styles, 4 outfits, 4 weapons — while the asset has far more.

## 2. Goals / non-goals

**Goals**
- Every card previews **the real look** on a hero model (no abstract dots).
- The shop is **grouped by category** with clear headers; nothing mixes.
- A **richer catalogue**: more colours, hair styles, outfit shapes and weapons, **plus 8 preset sets** (the sheet's own combos).
- Cards are legible at tablet size, with clear owned / wearing / locked / can't-afford states.
- Try-on on the mirror stays; buy/wear is one tap.

**Non-goals**
- No new scenes, no change to how coins are earned, no pricing rebalance beyond the new items.
- No change to the MakeHero flow beyond surfacing the new options.
- No network/Firestore changes (the existing `dungeonGallery` rules note still stands separately).

## 4. Design

### 4.1 One preview idiom: the card model

Replace both the colour dot and the cramped mini-hero with a single **card model**: a hero rendered in a fixed preview box, **standing on a soft floor shadow, clipped to the box**, showing the item applied to a base hero.

**Base toggle (decided):** the shop header has one small segmented control — **我的英雄 My hero** (default) / **中性模特 Model**. It switches *every* card model at once:
- **我的英雄** — the item applied to the child's own hero ("this is me with pink hair").
- **中性模特** — a fixed bland hero (one skin, plain short hair, plain tunic, no gear), so items are easy to compare side by side.

The toggle state is remembered in the registry, like `dungeon.shopTab`.

- Skin colour → base hero, that skin.
- Hair colour → base hero, that hair colour.
- Hair style → base hero, that style.
- Cloth colour → base hero, that colour.
- Outfit shape → base hero, that outfit.
- Weapon → base hero, holding it.
- Helmet / pet → base hero wearing it.
- **Set** → the whole preset look on the base (skin/hair/outfit/weapon applied together).

New helper (in `dungeon/art.js` or a small `dungeon/preview.js`):

```js
// Returns { node, setLook(look) } — a hero in a fake mirror, scaled to fit w×h, clipped.
export function heroPreview(scene, look, { w, h, view = 'front' } = {}) { … }
```

Implementation notes:
- Reuse `makeHero` + a rectangular geometry mask the size of the preview box.
- Scale by a **whole number** (NEAREST) so the hero stays crisp: `k = max(3, floor(min(w / 22, (h - 10) / 18)))`.
- Neutral card backdrop (a lighter inner panel), a soft ellipse shadow under the feet, no mirror frame.
- Keep `makeHero` cheap: it re-renders textures via `recolour`; cache is already keyed by colour — reuse across cards.

### 4.2 Catalogue information architecture

Split the catch-all 裝扮 into real categories, and add sets. **Decided: a sectioned single scroll with a category jump-bar** (fewer tabs than a 2-row nav, and it scales as the catalogue grows). Keep 頭盔 / 寵物 / 改造型 as before.

Sections inside the shop (only the ones that have items show):
1. **套裝 Sets** — the 8 preset looks.
2. **膚色 Skin** — colours.
3. **頭髮 Hair** — styles row, then colour row.
4. **服裝 Outfits** — shapes row, then cloth-colour row.
5. **武器 Weapons**.
6. **頭盔 Helmets** (existing SHOP tab).
7. **寵物 Pets** (existing SHOP tab).

Top bar becomes 4 pills: **裝扮 Looks** (sections 1–5) · **頭盔 Helmets** · **寵物 Pets** · **改造型 My hero**. Inside 裝扮, a sticky category bar (套裝 · 膚 · 髮 · 服裝 · 武器) scrolls the list to that section. Section headers are Chinese big + English small, with a thin divider.

### 4.3 Card anatomy & states

A single `card()` for every item type:

```
┌───────────────┐   preview box (fixed aspect, item applied to the model, clipped)
│   ▟▛ (model)  │   name: 大中文 (18px)  ·  small english
│  連身裙 Dress │   footer: price (art:coin)  |  ✓ 穿着 | 已擁有
└───────────────┘   states: default / trying(amber rim) / wearing(green + ✓)
 price / status    / owned / locked(chest·dragon silhouette) / can't-afford(greyed)
```

Rules:
- Name **never** overlaps the art (art is clipped above the name line).
- Tap = try on (free), the mirror updates, the action button (買 / 穿上 / 除下) updates.
- Locked (chest / dragon) items keep the silhouette + how-to-get line.
- Can't-afford: dim the price, keep the card tappable (try-on still allowed).
- Whole-item hit targets ≥ 48 CSS px.

### 4.4 Richer catalogue

**Pricing (decided: flat)** — one price for every item and every set, from a single constant `SHOP_PRICE` in `dungeon-logic.js` (start at **12**). No tiers. The card footer always shows the same number, so P1 children only have to compare "can I afford it?".

**Colours** — widen from the asset palette. Keep the same slots (`skin`, `hairColour`, `tunic`) but more entries, all at the flat price.
- `skins`: add a few more tones (e.g. pale, olive, deep) → ~9.
- `hairColours`: add white, purple, teal, pink → ~10.
- `tunics` (cloth colours): add mint, sky, plum, sun, black → ~12.

**Hair styles** — add the styles present in the sheet but not wired (confirm frames in the picker): e.g. ponytail, side-part, curly. `HERO_ART.hairStyles` 5 → ~8; `RC.hair` gains the frames; `pickStyle` modulo updates (tests).

**Outfit shapes** — 4 → keep 4 unless the sheet shows a distinct 5th (long robe). Recolour tone map already covers the teal variants.

**Weapons** — 4 → ~7: add **mace** (RC r0c47/48), **bow** (RC r0c52/53), **wand** (RC r0c42). Each needs a grip `{tex, frame, ox, oy, x, y}` in `RC.weapons` (verify on the hero before committing).

**Sets (decided: sets + individual pieces)** — new `LOOKS` table in `dungeon-logic.js`. Every piece is still buyable on its own; a set just buys and applies the whole combo in one tap:
```js
export const SHOP_PRICE = 12; // one flat price for every item and set
export const LOOKS = [
  { id: 'goldenPrincess', sex: 'girl', zh: '金髮公主', en: 'Golden Princess', price: SHOP_PRICE,
    hero: { skin: '#ffe0c4', hairStyle: 'long', hairColour: '#e0b050', tunic: '#e8903a' },
    equipped: { outfit: 'dress', weapon: null } },
  … 8 looks (girl + boy each) …
];
export const lookById = id => LOOKS.find(l => l.id === id) || null;
```
`buy` + a new `applyLook(progress, id)` set the hero fields and `equipped` weapon/outfit in one go (girl/boy chooses the corresponding preset).

### 4.5 Try-on / buy flow

- Tap card → try on (mirror animates, sparkle), action button updates.
- 買 → buy + auto-apply (as today), coins animate.
- Owned → 穿上 / 除下.
- Set → the mirror shows the **whole** preset; 買 applies hero + outfit + weapon atomically.
- Keep the voice lines; add one for sets ("換好新裝！").

### 4.6 Edge cases
- Long queue of cards: sections scroll; sticky category bar; `▼` hint stays.
- Resize: rebuild (existing handler) — the sectioned catalogue must rebuild cleanly.
- Less motion: no sparkle/tween.
- Hidden browser pane during QA: drive `game.loop.step(performance.now())` by hand.
